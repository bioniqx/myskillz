# FAST stays. SLOW searches against a program

Date: 2026-11-17. Status: design, not implemented. Scope: `glm-brainstorming`,
`glm-dev-team`, `glm-doc-generator`, `glm-git-diff-summary`,
`glm-requirements-code-audit`, `glm-systematic-debugging`, `glm-writing-plans`.
Nothing in `../claude-skills/` is touched. `glm-idea-to-spec` is out of scope.
Work on `main`. The session model and every `thoughtLevel` stay as they are.
No lane is promoted to GLM-5.3 or to any other model.

This file is the build procedure. Implement the steps in order. Do not start
a later step by weakening an earlier gate. Stdlib only.

## Decision

Two user-facing modes exist. The default is FAST, with no question. SLOW
starts only when the user says SLOW. FAST is the speed system that already
ships (explicit `MODE fast`, plus the direct and short shortcuts). There is
no third mode called normal.

SLOW does not raise quality by writing a longer prompt, by thinking longer,
or by sampling more implementations. The 2026-11-05 spec already closed that
door, and the later evidence agrees. On the work these seven skills own, the
highest quality a Flash-class session can force is: Flash proposes, a fresh
context attacks with evidence the author did not use to grade itself, and a
program re-runs that evidence before anything is allowed to count. Extra
test-time compute is spent only on that search. A passing suite, a confident
`APPROVED`, or a second essay on the same facts does not move the result.

SLOW is that search, turned on. FAST is that search, turned off, byte-for-byte
the current shortcuts. Width in SLOW fits the shape of the request. The oracle
is mandatory at every shape. A one-file edit does not grow three design lanes.
A design fork does not skip the breaker.

## What "highest quality" means here

Same bar as `docs/specs/2026-11-05-flash-opus-quality.md`, extended to the
four skills that spec did not cover.

| Skill | A SLOW result is allowed to ship when |
| --- | --- |
| glm-brainstorming | The engine named the option, every option was attacked, every load-bearing cite resolved, and a margin under 3 was asked. |
| glm-writing-plans | Every atom sits in one contract or in Out of scope, and each atom that a task quotes also sits in an assertion-shaped token in that task. |
| glm-dev-team | Strict profile, RED then GREEN, the green suite fails when one real assertion is removed, and every reproduced parent/slice blocker is fixed or named. |
| glm-requirements-code-audit | A closing status (MATCHED or CONFLICT) has a quote that is a substring of the cited lines, and a second fresh judge did not reproduce a counterexample against it. |
| glm-systematic-debugging | Exactly one diagnose is CONFIRMED, and the falsifier command the engine re-ran exited non-zero. |
| glm-doc-generator | Every behavioral sentence that remains carries a quote that is a substring of the cited file. Dropped sentences are listed, not softened. |
| glm-git-diff-summary | Every behavioral sentence that remains carries a quote that is a substring of the diff hunk. |

This is not a claim of Claude Opus 5.5 parity. The blinded 10+10 bar in the
2026-11-05 spec is still unrun. Taste, and any design fork whose margin is
under 3, stays with the user. A proof the engine cannot run is still refused.

## Why this is the ceiling

The 2026-11-05 kernel (atoms, fact ledger, `decide.py` score, RED then GREEN,
parent/slice attack, `APPROVED` ignored) is the floor and stays. SLOW adds
only the holes that floor still leaves open: a green suite that does not lock
behavior, a diagnosis with no falsifier, a document or a diff summary that
paraphrases, and a closing audit status seen by only one judge.

Public results that set this ceiling, none of them re-run here:

- Snell et al., ICLR 2025, "Scaling LLM Test-Time Compute Optimally". Search
  against a real verifier beats best-of-N, and on problems a smaller model
  already sometimes solves it can beat a much larger model. Where the verifier
  is a program (a test, a substring, a re-run command), SLOW spends compute.
  Where the verifier would be the same model scoring its own prose, SLOW does
  not spend.
- ICML 2025 spotlight, "Scaling Test-Time Compute Without Verification or RL
  is Suboptimal". Verification-free scaling falls behind as the budget grows.
  A longer SLOW chain of thought is the wrong purchase.
- SETS (arXiv 2501.19306) beats bare self-refine when the verify step has a
  signal. The 2026-11-05 spec already rejected same-evidence self-critique.
  SLOW keeps that rejection.
- TestSuiteBench (arXiv 2610.13065, 165 apps). Frontier agents write suites
  that mostly pass and still kill under 60% of mutants. DeepSeek V4 Flash in
  that table kills 28.6%. "Tests passed" is not the quality bar. One
  mechanical mutant after GREEN is the check this harness can run without a
  new model.
- VibeCheck (arXiv 2609.05978) and the Momentic audit of 1,000 agent-written
  tests (about 9.6% useful). An independent checker in a fresh context finds
  defects the author misses. The harness has one model family, so independence
  is hidden rationale plus a command the engine re-runs, which is the breaker
  rule already in `decide.py`. Five providers are out of scope because the
  model must not change.
- Van Deth, June 2026, cited by the 2026-11-05 spec. Moving the same GLM onto
  a real agent loop closed most of the gap to Opus. These skills are already
  that loop. Another layer of `SKILL.md` rules will not move it again.

## Rejected

- A third mode that keeps today's "normal" gates. Those gates are a subset of
  SLOW. Keeping them would be a mode.
- More rules in `SKILL.md`. Bodies are already at the size where the middle
  is dropped. Each skill gains a pointer, not a second copy of this file.
- Promoting any lane, or raising `thoughtLevel`. Max effort is already the
  latency dial. It does not lock a test, a cite, or a diagnosis.
- Best-of-N implementations, majority vote, or a second essay on the same
  evidence. Correlated samples share the weak test.
- Best-of-N designs beyond the three lenses already required. A fourth lens
  is not generated.
- Full mutation campaigns, coverage targets, or a new test framework.
  One assertion deletion is the floor. It proves the file can fail. It does
  not prove every atom is locked. Upgrade path: one mutant per quoted atom,
  still mechanical, still after GREEN.
- A startup question. The default is FAST. The tools never print an ASK block
  and never wait for a mode choice. SLOW still asks, once a SLOW run is
  already going, for a margin under 3, for taste, and for the three stops
  FAST already has (dirty checkout after one stash, agents installed this
  session, irreversible actions).
- Silent auto-pick of an unattacked or all-broken set. That remains a FAST
  behavior (`ask.py fast`). SLOW never calls `force_pick`.

## Mode contract

One classifier, `mode_of(text, stamped)`, living in `_shared/handoff.py`.
`glm-brainstorming/scripts/ask.py` imports it. No second copy of the regex.
The return is `fast` or `slow`. There is no `ask` result.

Tokens, after `check.fold_ascii` for the lowercase forms. `FAST` and `SLOW`
in capitals also match as whole words.

- SLOW phrases: `slow mode`, `che do slow`, `che do chat luong`,
  `uu tien chat luong`, `quality mode`, `--slow`, `/slow`, and the capital
  word `SLOW`.
- FAST phrases stay the ones in `ask.py` today (`fast mode`, `che do fast`,
  `dung fast`, `--fast`, `/fast`, and the capital word).
- A refusal (`khong`, `no`, `without`, `do not`, within 30 characters) blocks
  that mode. Refusing FAST does not select SLOW.
- If both positives survive, the later match in the text wins.
- If SLOW is the only survivor, the result is `slow`.
- If the text names neither mode, keep `stamped` when it is `fast` or `slow`.
  A missing stamp, an empty text, and a stored `normal` are `fast`.
- New writes never say `normal`.

A follow-up that does not name a mode leaves a SLOW run in SLOW. A follow-up
that says FAST, or that refuses SLOW, stamps `fast`.

Who writes the stamp. `handoff.py open` writes
`<git toplevel>/.claude/dev-team/mode` as one line, `fast` or `slow`, plus
the unix time, same directory rules as the existing pace file. Brainstorming
still writes `.brainstorm/drafts/mode.json` through `ask.py`, with `fast` or
`slow` only. `ask.py mode` prints `MODE fast` or `MODE slow` and does not
print an ASK block.

No mode word is FAST, including a heavy request (`login`, a long spec, a
full doc catalog):

- Brainstorming takes today's `PACE fast` path when `pace_of` is `full`, and
  today's direct or short path when the shape matches. It does not ask.
- The other six skills take their FAST branch below, not the old full or
  normal pipeline.

`fast.md` gains one ending only: after `devteam finish`, run
`handoff.py fast-done`, then show `COMMIT` and `GITLAB` in the chat. SLOW
never tells the model to read that file. When the prelude prints
`PACE: direct` or `PACE: short` under FAST, that file already yields.
Leave that sentence. Delete the startup question from
`glm-brainstorming/SKILL.md` (`Dùng chế độ FAST không?` and `MODE ask`).

FAST commits when its own check has passed, and not before. `handoff.py
fast-done` commits only the paths named on its command line, and only when
those paths are still dirty. It never pushes, never amends, and never adds
a trailer. The message and the GitLab note are English. The chat shows both
so the user can copy them. A chain step that hands off does not commit.
An already-committed path does not become a second commit. SLOW does not
call `fast-done`.

The last `NEXT:` line still wins. Every SLOW branch prints its `NEXT` last.

## The three spends

All three are engine code. A `SKILL.md` sentence that merely asks for them
is not the feature.

### 1. Independent oracle

The attacker sees the frozen atoms and the artifact. It does not see the
author's tradeoff prose. It returns a command or a `path:line`. The engine
re-runs it. A `NO-BREAK` or `APPROVED` with nothing re-run is ignored.
`injectAgentsMd` stays false on those agents. No new agent file is required
where one already exists (`glm-design-breaker`, `glm-spot-reviewer`,
`glm-doc-reviewer`). Doc and diff use the existing reviewer or one
`general-purpose` lane whose prompt is the printed `PROMPT` from a new
`handoff.py` helper only if a dedicated agent would duplicate `decide.py`.
Prefer no new agent: the checker is the program.

### 2. Oracle strength

A check that cannot fail does not count.

- Code, after GREEN, only when the stamp is `slow`. In a throwaway checkout
  of the slice commit, delete one assertion and re-run the slice test
  command. Python: the first `ast` `Assert` node, rewritten as `pass`, file
  written beside the original. Other languages: the first line matching
  `assert`, `ASSERT`, `expect(`, or `CHECK(`, deleted. Try up to three
  sites. A mutant that does not parse is skipped. A mutant whose test exit
  is non-zero means the suite can fail: discard the throwaway and continue.
  A mutant that parses and whose tests still exit 0 is `MUTANT weak`. The
  engine re-opens RED with that mutant diff in the briefing, cap 2, then
  names the leftover to the user and does not merge that slice. No
  assertion-shaped line at all is `MUTANT skip`, not a blocker. The atom
  literal check already covers a missing quote. Production code is never
  mutated.
- Debug, only when the stamp is `slow`. `close` treats a diagnose as
  CONFIRMED only when `experiments.json` contains a `falsify` command that
  this process re-ran and whose exit was non-zero. A missing falsifier
  prints `NEXT:` asking for that one command, cap 2, and does not print
  `ROOT CAUSE`. A scan hit stays a lead.
- Docs and diffs. `decide.py claim` reads `CLAIM <quote> :: <loc>` on stdin.
  It keeps the line only when `quote` is a substring of the bytes at `loc`
  (a file, or a diff chunk path the gather step already wrote) and is 25
  words or fewer. Otherwise it prints `DROP`. The model deletes the
  sentence or binds a real quote. Cap 2. Survivors are the only behavioral
  sentences in the published text. Dropped lines are printed once as
  `UNVERIFIED`, not rewritten into hedged prose.
- Audit. A MATCHED or CONFLICT with a quote that is not a substring cannot
  close, which is already the rule. SLOW adds the second judge below.
- Design. SLOW never calls `force_pick`. An unattacked option cannot win.
  On the score leader only, one more breaker runs with the fact list
  reversed. A reproduced counterexample removes that option and `score`
  runs again. Leave-one-out on margin 3 or 4 stays as it is.

### 3. Fitted width, capped repair

`pace_of` still computes `direct`, `short`, or `full`. Under SLOW it selects
width. It never selects "skip the oracle".

| Shape | SLOW width | Oracle that still runs |
| --- | --- | --- |
| direct | No design lane, no plan, no dev-team. The named file, tests first. | Atoms from the request, `claim` on the new assertion, mutant after the test passes. |
| short | At most 3 files, in session. One attacker. | Same oracle. The attacker sees the contract and the diff. |
| full | Today's full pipeline for that skill. | The spends above, on top of the 2026-11-05 gates. |

Repair caps stay inside the script. Design and plan keep their current caps
except where a step below changes a number. After the cap, name the leftover.
Do not open a fourth orchestrator turn.

`prove --cap` defaults to 4. SLOW passes `--cap 8`. Further web facts stay
`UNPROVEN`. `--offline` still opens no socket.

## Per skill

### glm-brainstorming

FAST, the default, including a full request that never says SLOW: today's
`PACE fast` prelude and today's `fast.md`. Direct and short shapes still
take those shorter NEXT lines. No question.

SLOW and `full`: do not read `fast.md`. Round 1 is atoms plus fact lanes.
Round 2 is three drafters and three breakers, then `check.py close`. Then
the extra breaker on the leader. `prove --cap 8` on the load-bearing web
facts. `DECISION ask` is a user question. `DECISION stop` stops. The design
is shown only after `send` prints `fail=0`. Human approve stays. Chain to
writing-plans only when the user asked to implement or approve returned yes.
`chain.json` then has `"mode": "slow"` and `"continue": true`.

SLOW and `direct` or `short`: the fitted-width row. Do not start the chain.

### glm-writing-plans

FAST, the default for any spec length: today's inline path, no `build`.

SLOW: ignore the inline path and ignore a fast chain. `brief`, then
contracts, then `build`. `--repairs` is 3, read from the stamp inside
`plan_tool.py`, not from the model remembering a flag. The existing in-build
split for a contract over 80 lines or over four files always runs (no
`--no-split` under SLOW). A second decomposition is that split, scored by
`analyze` plus atom coverage. It is not a new orchestrator call. A task that
quotes an atom and has no assertion-shaped token (`assert`, `expect`,
`CHECK`, or the atom inside a `Run`/`Expected` fence) is `ERR`. Deep stays
Flash at max. The model id does not change.

### glm-dev-team

FAST, the default: today's direct, short, quick, and fast paths, including
when the request is heavy and never says SLOW. High-risk slices keep RED,
GREEN, and review.

SLOW: delete any `short` or `fast` pace file in that same `open` so a stale
FAST stamp cannot win. Force profile `strict`. `apply_quick` returns false.
Do not launch `glm-team-leader` only when today's full path already skips
it; SLOW full uses the leader for plan adoption the way strict does today.
Every code slice is RED then GREEN. After green proof passes, run the mutant
gate before `glm-spot-reviewer`. The parent/slice attack matrix is
unchanged. `APPROVED` is ignored. `turbo` and `spike` are refused while the
stamp is slow, even if the plan asks. The conductor says `PROFILE strict`
and `MUTANT` in one line when it happens.

### glm-requirements-code-audit

FAST, the default for any spec length: today's short checklist path.

SLOW: ignore that short path. Checklist, then `run`. For each
MATCHED or CONFLICT, `audit.py` makes one more judge call in the same
fan-out wave. The prompt is the checklist item plus the cited lines and
nothing else. The judge returns `COUNTEREXAMPLE` plus a command or a
`path:line`, or `NO-BREAK`. The engine re-runs a command when one is
present, and re-checks the quote as a substring either way. A reproduced
counterexample sets CONFLICT. A quote that is not a substring drops the
finding. No API key: the existing agent lane, one batch, same prompt rule.
The substring check still runs locally. `--accept` still cannot copy an
unattacked status.

### glm-systematic-debugging

FAST, the default: the two-round path. A probe that would have printed
`LANE: SWARM` still prints `LANE: FAST` unless the stamp is slow. The first
flaky measure stays `stress.sh -n 40`.

SLOW: the probe's `LANE: FAST` is printed as `LANE: SLOW` instead, and the
prelude does not take the direct branch. Two hypotheses, a control and a
treatment, then `close`. A regression phrase (`worked before`, `regression`,
`bisect`) with a range runs `bisect-parallel.sh` before the fix experiment.
Flaky measures use `stress.sh -n 200`. `close` applies the falsifier rule.
A FIX line still needs a CONFIRMED `role=fix` experiment. One confirmed
diagnose still prints `ROOT CAUSE` from the file, not from the model's draft.

### glm-doc-generator

FAST, the default: write from the recon without a reviewer wave, including
a full catalog that never says SLOW.

SLOW: always run `recon.sh`. Ignore `_doc_pace` direct. The writer produces
the document plus `CLAIM` lines. `decide.py claim` filters them. One
`glm-doc-reviewer` pass sees the document and the recon map. Its
counterexample is a `CLAIM` the engine checks. A sentence `claim` dropped
is deleted. Reviewer agents are not limited to api-reference, data-model,
and configuration under SLOW. One reviewer wave, cap 8, is enough.

### glm-git-diff-summary

FAST, the default: today's markers. INLINE and ONLY_NOISE stay one write.
READ stays one parallel Read. FAN_OUT stays at most 8 agents. No claim pass.

SLOW: gather still runs and the same marker still decides width, except the
published text goes through `decide.py claim` against the chunk files
gather wrote. A FAN_OUT chunk with zero surviving claims is re-dispatched
once. A second empty result is `UNVERIFIED` for that chunk, not a guess.
`NOT_A_REPO`, `EMPTY_DIFF`, and `NO_BASE` still stop in one line.

## How to build it

Do the steps in order. After each step run the command in that step. Fix a
red test before the next step. Do not edit `fast.md` except to leave it
unread by SLOW. Do not edit agent `model` or `thoughtLevel`. Do not install
into `~/.zcode` in these steps.

### Step 1. Classifier

Edit `_shared/handoff.py`. Add `mode_of(text, stamped)` with the contract
above. Move the FAST regex out of `ask.py` so `ask.py` imports it from the
vendored `handoff.py` beside it. `ask.py mode` never prints `ASK`.

Tests, new class in `_shared/tests/`, stdlib `unittest`:

- `FAST` and `che do fast` return fast.
- `SLOW`, `che do chat luong`, and `uu tien chat luong` return slow.
- `khong dung fast` returns fast. Empty text returns fast.
- `khong dung slow` returns fast.
- `FAST ... SLOW` returns slow. `SLOW ... FAST` returns fast.
- Text with no mode word and stamp `slow` returns slow.
- Text with no mode word and stamp `normal`, or no stamp, returns fast.

```bash
cd glm-skills && PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover -s _shared/tests -t _shared/tests -p 'test*mode*' -v
```

### Step 2. Prelude

In `_prelude`, at the top of each of the seven skills, compute the mode.

- `slow`: print `PACE: slow`, write the mode stamp, clear a pace file whose
  first field is `short` or `fast`, print the SLOW `NEXT` from "Per skill",
  and return. Do not fall through into the FAST branch.
- `fast`: today's FAST branches, including a heavy sentence that never says
  SLOW. Stamp `fast`. Do not print an ASK block.

Add one unittest per skill that feeds a one-line stdin containing `SLOW` and
asserts the binding `NEXT` contains `PACE: slow` and does not contain
`read fast.md`. Add one unittest that feeds `login` with no mode word and
asserts the brainstorming `NEXT` is the current `PACE fast` sentence and
contains no `ASK`. Use the existing handoff test module if one already
covers `open`. Do not hit the network. Preludes that need a repo use a
temporary git directory.

```bash
cd glm-skills && PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover -s _shared/tests -t _shared/tests -p 'test*handoff*' -v
```

### Step 3. `claim` and `prove --cap`

In `_shared/decide.py`:

- `prove` accepts `--cap N`, default 4, N clamped to 1..8.
- New CLI `claim`. Stdin lines `CLAIM <quote> :: <loc>`. `--root DIR`
  resolves `loc`. A file loc uses the existing cite window. A loc under the
  gather chunk directory compares against that chunk's bytes. Print `KEEP`
  or `DROP` per line, then `RESULT claim keep=<n> drop=<n>`.

Vendor `decide.py` to `glm-doc-generator` and `glm-git-diff-summary` by
adding them to `decide_skills` in `_shared/sync.sh` and to the `decide.py`
list in `_shared/tests/test_vendored.py`. Do not add `glm-idea-to-spec`.

Offline tests: a quote that is a substring is KEEP; a paraphrase is DROP;
`prove --offline --cap 8` does not call `urlopen`; cap 4 remains the default.

```bash
sh glm-skills/_shared/sync.sh
cd glm-skills && PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover -s _shared/tests -t _shared/tests -p 'test*decide*' -v
cd glm-skills && PYTHONDONTWRITEBYTECODE=1 python3 -m unittest _shared/tests/test_vendored.py -v
```

### Step 4. Mutant gate and strict profile

In `glm-dev-team/scripts/devteam.py`, when the mode stamp is `slow`:

- Profile is `strict` even if the plan says turbo, spike, or a `--fast`
  level.
- `apply_quick` does not mark slices.
- After green proof exits 0, run the mutant procedure in "Oracle strength"
  in the same proof pool, cap 4 local threads, before review dispatch.
  Print `MUTANT weak`, `MUTANT ok`, or `MUTANT skip`.

Unit tests on a temporary file tree, no model call: a Python function with
`assert result == 1` that still passes after the assert becomes `pass` is
`MUTANT weak`; the same file whose remaining assert fails after the first
is removed is `MUTANT ok`; a file with no assert is `MUTANT skip`. A plan
with `profile: turbo` under a slow stamp reports `PROFILE strict`.

```bash
cd glm-skills && PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover -s _shared/tests -t _shared/tests -p 'test*devteam*' -v
bash glm-dev-team/scripts/selftest.sh
```

The selftest must stay green. Add one selftest section for the slow stamp
if the unit test cannot see `init`. Do not weaken an existing section.

Tests: a long spec with no slow stamp still takes the inline path. The same

### Step 6. Debug falsifier

In `glm-systematic-debugging/scripts/debug_tool.py`, when the mode stamp is
`slow`:

- `close` refuses `ROOT CAUSE` unless the single diagnose has a falsify
  command this process executed with a non-zero exit.
- Probe output that would say `LANE: FAST` says `LANE: SLOW` instead.
- The prelude maps that marker to the SLOW `NEXT`, not to `PACE direct`.

Tests, no network: under a slow stamp, one CONFIRMED diagnose and no
falsify prints no `ROOT CAUSE`. The same file plus a falsify record whose
stored exit is non-zero prints `ROOT CAUSE`. With no stamp, a probe that
would swarm still reports `LANE: FAST`, and `close` accepts today's single
CONFIRMED diagnose. The experiment runner, not the model, is what writes
the exit code. A test that only puts `"status": "CONFIRMED"` in JSON must
not pass the slow gate.

```bash

```
